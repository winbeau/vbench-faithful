## Reference dependency evidence

The clean reference fork `/home/msy625/vbench1` at commit `13dee903cc97e2633ed6e8f50dea61bc90717935` declares broad dependencies in `requirements.txt`, including NumPy `<2.0.0`, SciPy, OpenCV, PyTorch-related packages, `openai-clip`, decord, and `transformers==4.33.2`. The root `setup.py` performs a CUDA-enabled PyTorch check. Dynamic Degree additionally imports `easydict`, `tqdm`, and bundled RAFT code.

These observations are not enough to select final exact uv versions: the reference requirements are not a complete cross-metric dependency closure, model code includes vendored third-party code, and the installed PyTorch build cannot be exercised without CUDA. Dynamic Degree therefore declares direct dependency names and the upstream NumPy bound without pinning unverified model versions. No lock file was hand-written.

## Current decision (2026-09-14)

- The current reference is the official Vchitect/VBench checkout at the fixed SHA recorded in `configs/upstream.toml`; the older `/home/msy625/vbench1` environment and fork are historical evidence only.
- `.python-version` pins Python 3.11.14. uv 0.9.17 is pinned in CI and the checked-in lock is generated by uv rather than hand-written.
- Each metric declares direct scientific imports in its base dependencies. Model-only closures are in the package `models` extras, and the root `models` extra aggregates all eight packages. Motion Smoothness no longer depends on Dynamic Degree as a distribution.
- The test group is explicit (`uv sync --locked --group test`) and contains scientific/test tooling. Existing model-contract tests additionally use the verified CPU-only overlay `torch==2.14.0+cpu` (`uv pip install --python .venv --index https://download.pytorch.org/whl/cpu 'torch==2.14.0+cpu'`, then `uv run --no-sync --group test pytest`); this overlay is separate from the default model-free sync and does not belong to `uv.lock`.
- No model checkpoint is present in this workspace run, so RAFT/UMT/DINO/ViCLIP/GRiT loading and parity are not verified here. The model extras describe the known Python closure only; they do not provide weights, CUDA or compiled Detectron2.
- Official backend runtime and numerical parity remain unverified in this workspace because required weights, CUDA combinations, and some external builds are unavailable.
- Spatial Relationship additionally requires the official checkout's vendored GRiT/CenterNet2 source and a compatible Detectron2 build. The reference requirements comment out an unpinned Detectron2 Git dependency, so no version is invented in this workspace.
- `uv.lock` is the source of truth for Python dependency resolution; run `uv lock --check` and `uv sync --locked` after changing metadata. External source checkouts, compiled Detectron2/GRiT builds, drivers and model files are intentionally outside the lock.
- Model files must remain outside Git and `uv.lock`, with SHA-256 recorded in run metadata.

The PyPI `decord==0.6.0` artifact has a misleading wheel filename/metadata
tag on this host (the internal tag is `cp36-cp36m-manylinux2010_x86_64`). Its
import succeeds under the verified Python 3.11 environment, but `uv pip check`
can report the platform mismatch and it is not evidence of full model-runtime
compatibility. Scene keeps decord in its `models` extra so the default
model-free sync and CLI help do not install or import it. Real video decoding
with decord was not exercised in this run.

## Research-script portability

The resumable official-repair script now respects caller-provided upstream,
DINO, GRiT, and `PYTHONPATH` settings; it does not supply private workstation
paths. Other archival research scripts still contain references to external
`/root/autodl-tmp` storage from their historical runs. They require explicit
data, checkpoint, toolchain, and environment configuration before use and are
not advertised as portable workspace commands. Frozen research data is never
modified as part of that configuration.
