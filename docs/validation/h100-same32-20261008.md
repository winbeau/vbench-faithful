# Same-32-video H100 timing experiment

The user selected **the same 32 videos in all 16 dimensions**, with supplementary per-dimension queries. The cohort is fixed before scoring in [the reviewed annotations](../../configs/benchmarks/same32-20261008.json): 32 distinct ModelScope videos, each 256×256, 16 native frames at 8 FPS, 2 seconds long; 64 seconds of source media in total. There are 512 dimension–video records per backend, not 512 independent videos.

Selection sorts `human_action/*-0.mp4` by SHA-256 of `vbench-speed32-v1:` plus the filename and takes the first 32. Native frames 0, 7 and 15 were reviewed to author supplementary scene/object/color/spatial/style queries. Explicit negative probes remain in the manifest, including generated clips without their intended human subject. These are agent-authored diagnostic queries, not official annotations or human preference ground truth. Original action prompts and filenames remain unchanged because upstream Human Action reads its labels from filenames. No video was selected or removed based on a model score or detection.

Both backends receive the identical 512-record manifest (`803e938bc5ac2c7deaedc4246870e94756510df27f91cf246a6b364729cbfa65`). Media are referenced in place; frozen research data and scores are untouched. Missing scores remain null with the full denominator. This experiment measures execution speed and equivalence across implementation versions, not relative metric quality.

Measurements use only physical H100 GPU 3 (`GPU-c0af33a9-498c-ff7c-bb56-e9992ccded30`). GPUs 0–2 belong to unrelated processes. Runs are sequential, with dependencies/weights already present, and no previous-run result reuse. Wall-clock timing includes Python/uv startup, verification, model loads, inference and outputs; downloads are excluded. The official reference is VBench `fd18b3d055cb0fc6f066ca90fe2c3c8cbb698490`.

## Reproduction

```bash
uv run python scripts/prepare_speed32_inputs.py \
  --video-root /path/to/vbench-1.0-human-preference/videos \
  --output output/speed32-inputs.json
uv run python scripts/eval.py --config /path/to/benchmark.yaml \
  --backend origin --dimensions all --gpus 3 --no-reuse --output output/speed32-origin
uv run python scripts/eval.py --config /path/to/benchmark.yaml \
  --backend repair --dimensions all --gpus 3 --no-reuse --output output/speed32-repair
```

Use the generated manifest as YAML `input` and the pinned runtime inventory as `assets`. The supplementary `scripts/benchmark_vbench_native.py` calls all upstream compute APIs in one process using the same prepared metadata. Its compute loop matches `VBench.evaluate`, while bypassing the filename-based metadata builder so each dimension can receive its reviewed query. It uses the same three CPU threads and TF32 settings as the isolated workers, with no repair-side inference sharing.

An initial scene metadata nesting error was interrupted and retained as `origin-baseline`; it is excluded from every timing comparison. The corrected manifest is immutable across valid measurements.

## Measured overview

| Execution | End-to-end seconds |
| --- | ---: |
| Original VBench compute APIs, one process | 338.50 |
| Original VBench through isolated per-dimension workers | 516.34 |
| Nine repairs + seven official fallbacks, before | 554.19 |
| Nine repairs + seven official fallbacks, first optimization | 429.78 |

The first optimization saves **22.45%** against the same repair pipeline, but remains **26.97% slower** than the upstream single-process API. It is not yet a match for native VBench. All figures include fresh inference; no previous-run artifacts were reused. Spatial and Multiple Objects each reused 512 ObjectDet frame outputs produced inside this same run. Object Class and Color each inferred 510 distinct frames and reused two identical frames locally; the two model protocols remain separate.

All 288 repaired input records retain exactly equal scores and statuses, including failures. Raw semantic outputs, visual evidence and normalized diagnostics—including dereferenced, hash-verified instance evidence—match exactly. Seven unchanged official dimensions and the native-versus-isolated official comparison pass the recorded 1e-6 tolerance; the latter has maximum score error 1.995e-8. These are timing-cohort checks, not parity to the historical E0 research cohort.

Coverage is incomplete and must accompany the timing: official Color returns 25/32; repaired Subject 23/32, Spatial 11/32 and Color 9/32. Every other task returns 32/32. All 32 videos reached visual inference in both GRiT protocols. Spatial failures include generated `on`/`in front of` relationships rejected by the selected four-direction scorer. No failed input was removed or given a zero score. The benchmark does not establish relative repair quality.

The [machine-readable receipt](h100-same32-20261008.json) records every dimension's timing, coverage, SHA, hardware and equivalence check. Regenerate it with `scripts/summarize_speed32.py --experiment <retained experiment directory> --output <new JSON>`.

The user subsequently requested two product modes: original VBench, and a default project mode with nine unchanged repairs plus seven accelerated implementations. Those seven implementations must pass per-video `abs(candidate-reference) <= max(1e-6, 0.01*abs(reference))`.
