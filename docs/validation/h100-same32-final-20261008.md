# Same-32 final sixteen-dimension acceptance

The default project command completed all sixteen dimension tasks in **344.60 s**, down from **554.19 s** before optimization (**37.82% less time; 1.61×**). The original VBench command took **345.58 s**, and a direct single-process original API baseline took **338.23 s**. The project is within **1.88%** of the direct original baseline; this measurement establishes near parity, not a statistically significant speed advantage.

All seven accelerators pass the agreed per-video numerical gate on **224/224 records**. The nine repairs preserve all **288 input identities, statuses and non-numeric evidence fields**; eight dimensions have exact normalized result rows, while Subject has small floating-point differences described below. These are real H100 model runs, with **zero previous-run inference-cache hits**.

All sixteen tasks ran, but the selected repair contracts do not score every supplied query. Project coverage is **459/512**, including **235/288** in the nine repairs; original coverage is **505/512**. This is an end-to-end timing and numerical regression experiment on a fixed cohort, not complete successful scoring of 512 records or a rerun of the paper's research tables.

Machine-readable clocks, commands, per-dimension results, acceptance checks, media identities and per-video durations are in [the final receipt](h100-same32-final-20261008.json). The [work record](../plans/2026-10-08-speed32-optimization.md) links each sequential optimization and its independent acceptance.

## Cohort and measurement

- **Same media for every dimension:** 32 distinct ModelScope Human Action `*-0.mp4` files, selected by sorting SHA-256 of `vbench-speed32-v1:` plus the filename and taking 32 before inspecting model scores. All are native 256×256, 16 frames, 8 FPS, **2.000 s each / 64 s total**. Original filenames are retained for the official Human Action lookup.
- **Queries:** the [fixed configuration](../../configs/benchmarks/same32-20261008.json) contains supplementary dimension metadata. An agent reviewed frames 0, 7 and 15; missing targets remain negative probes. These queries are not official preference labels or independent human truth. The input builder is [prepare_speed32_inputs.py](../../scripts/prepare_speed32_inputs.py).
- **Device:** `h100-server`, physical GPU 3, NVIDIA H100 80GB HBM3, UUID `GPU-c0af33a9-498c-ff7c-bb56-e9992ccded30`, driver `590.48.01`. All dimensions run sequentially on this device. Unrelated processes were not stopped.
- **Timing:** an outer monotonic clock surrounds each complete command, including uv/controller startup, verification, environment preparation, model loading, inference, result writing and cleanup. Final order was `official`, `ours`, then direct original. Each was measured once. The selected GPU was free at each start; workloads on other GPUs changed, and OS filesystem caches were not cleared. The roughly one-second difference between the two controller commands should be treated as a tie.
- **Cache:** `--no-reuse` disables previous-run stage reuse. The project still shares identical GRiT frames and ViCLIP video features inside this new evaluation, with explicit receipts. The original baseline does not use these optimizations. This is fresh inference with existing runtimes/weights, not a first-time download/install benchmark.
- **Original execution:** `official` calls the pinned upstream compute functions in one persistent process per selected GPU. All sixteen requests used PID `714348`. The direct baseline follows the original single-process dimension loop through [benchmark_vbench_native.py](../../scripts/benchmark_vbench_native.py), using the same prepared metadata. Neither comparison is the stock upstream filename-based input builder.

## GRiT group and retained repair logic

The four GRiT stages total **164.66 s** in the final run, versus **200.52 s** in the first optimized full run and **218.64 s** for the final direct original stages. Their optimization was handled together as authorized:

1. Skip unused display rendering and share byte-identical ObjectDet input-frame evidence across Object Class, Spatial Relationship and Multiple Objects. This avoids 1,024 repeated frame forwards on this cohort. Color's DenseCap evidence uses a separate cache namespace.
2. Reuse a copied ObjectDet ROI/text-head result only when the model, decoder settings and feature/proposal objects agree. Both raw evidence heads remain available; the cohort removed 510 redundant head forwards. Color's two heads differ on all 512 inspected frames, so both are retained.
3. Batch the same semantic requests in groups of 32. All raw text, compiled targets and scoring rules remain unchanged. Each dimension still owns its formula and runs in its own environment.

Scene and Human Action also batch their original semantic requests; Subject batches each video's DINO frames. The Background SAM CUDA-graph candidate was withdrawn because the whole-dimension gain was unproven. Dynamic retains its aligned-v1 native protocol. Detailed profiles and receipts remain in the work record.

Final repair comparison against the pre-optimization repair reference checks paths after normalizing only run-specific artifact locations. Eight dimensions have exact normalized rows. Subject has **62 changed floating diagnostic/score fields**, maximum absolute difference **2.980232238769531e-7**; the maximum score difference is **1.1920928955078125e-7**. All are below the tight **1e-6 absolute tolerance**. This is numerical agreement, not bitwise equivalence. Localization/crop diagnostics agree; no claim of separately hashing every intermediate mask is made.

Coverage and failure states match the original repair reference. Subject retains nine unscored inputs under its localization contract; Spatial scores eleven, with unsupported relations such as `on` and `in front of` preserved as failures; Color scores nine under its selected target/compiler contract. All 32 videos still enter each GRiT visual stage. Some unsupported Subject inputs stop before DINO under the existing logic. These different scoring contracts and early exits limit cross-method timing interpretation; no annotations were changed to improve the timing or denominator.

## Seven-dimension numerical acceptance

Every input is matched to its official counterpart. The gate is:

```text
abs(candidate - official) <= max(1e-6, 0.01 * abs(official))
```

| Temporal Flickering | 32/32 | 0 | 0 |
| Aesthetic Quality | 32/32 | 0 | 0 |
| Imaging Quality | 32/32 | 2.0266e-5 | 3.4568e-7 |
| Temporal Style | 32/32 | 2.2352e-7 | 4.1985e-6 |
| Overall Consistency | 32/32 | 1.7881e-7 | 2.1579e-6 |
| Appearance Style | 32/32 | 0 | 0 |

The largest relative error is **0.00041985%**. Imaging retains native 0–100 per-video MUSIQ scores and the upstream /100 dataset aggregate. All seven native reducers pass their aggregate checks. Appearance's aggregate differs by 1.94e-16 despite identical per-video scores because of floating summation order.

Temporal computes eight batches of fresh ViCLIP features; Overall reuses all eight in this run and has zero misses. Text prompts and scores remain separate. Overall's standalone speedup is not established. No mixed precision or frame subsampling was introduced to meet these timings. Numerical agreement on this cohort is not a human-quality guarantee for arbitrary videos.

The final persistent official mode also matches the direct original baseline: fifteen dimensions' scores are exact, while Motion's maximum score difference is **1.9946e-8** and aggregate difference **1.7809e-10**. Original Color omits seven records. The controller retains these missing inputs with null scores and returns exit code 1; the native API baseline returns 0 despite the omissions. Ours also returns 1 for its existing partial coverage. Neither partial task is presented as a complete-population mean.
