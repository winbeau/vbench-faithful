All runs used four NVIDIA H100 80 GB HBM3 GPUs, physical indices 0–3, driver `590.48.01`. Dimensions ran concurrently in four lanes; each worker saw one device as `cuda:0`. Runs in this table were executed sequentially, with dependencies and weights already restored. Time includes asset hashing, CUDA probes, environment checks, worker startup, and result writing; it excludes restoration/downloads.

| Run | Effective tasks | Input records / unique media hashes | Cache hits | Four-GPU wall time |
| --- | --- | --- | --- | --- |
| `origin-final-cold` | 16 Origin | 16 / 11 | 0 / 16 | 52.29 s |
| `repair-final-cold` | 9 Repair | 19 / 16 | 0 / 9 | 105.07 s |
| `origin-final-warm` | 16 Origin | 16 / 11 | 16 / 16 | 17.41 s |
| `mixed-final-warm` | 9 Repair + 7 Origin | 26 / 21 | 16 / 16 | 33.60 s |

“Cold” means fresh stage inference at the tested code identity; the operating-system file cache and restored runtimes were already available. Warm runs still validate dependencies and probe CUDA. They reuse artifacts and are **not fresh model inference**. These small fixtures do not establish large-dataset throughput or a general inference speedup.

An input record is a manifest identity, not necessarily an independent video: several dimensions use identical media. Official acceptance uses one record per dimension. Repair uses original/counterfactual pairs for eight dimensions and one original plus two counterfactual clips for Dynamic. The mixed manifest combines the same 19 repair records with seven official-only records. Video duration comes from FFprobe; GIF duration uses the sum of explicit frame delays when available. GIFs lacking positive explicit delays retain an unknown duration (`null`); no FPS is assumed. Every duration and its source is retained in the JSON receipt.

The two warm runs passed **32 task comparisons**: exact per-video rows and official native aggregates equal their fresh counterparts; every reused stage is marked cached and `fresh_inference` is false. The mixed run specifically verifies reuse after changing the selected dimension set and combining separately computed Origin and Repair tasks.
