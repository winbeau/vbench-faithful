# Subject repair：官方全量扩展与背景干预

2026-09-20。**官方 1440 条视频与扩大的背景实验已完成。初轮隔离裁剪版明显退化；后续 CLS＋缺失证据回退候选缓解了退化，但仍未证明整体修复优秀。** 后续在统一零平局容差下，test 准确率 origin 为 58.45%、原隔离版 48.76%、新候选 57.05%；34 条完整背景干预的平均分差分别为 0.060218、0.191112、0.053575。全部阶段、失败和分母均保留。

初轮按 dev 校准平局容差的结果为 origin 58.53%、原聚合 repair 59.61%，改善约 1.09 个百分点且配对区间跨零。下文分别注明评估规则，避免把不同容差或 dev/test 的分数混比。此前咖啡、吉他两条的背景改善不能推广成总体修复成功。

用户随后明确：主体大体识别正确、主要部分保留即可，容许约两成不精确；不再因少量边缘漏分或背景混入暂停实验、反复要求轮廓确认。这里的“约 80%”是选材/定位的实用容忍标准，未测量人工轮廓 IoU。本轮重点是背景稳定性、主体变化响应和整体偏好表现。

## 为什么之前范围小、数值看起来低

之前只完成了小规模背景构造诊断，并非服务器上只有两条或七条 Subject 数据。`h100-server` 已有官方 Subject Consistency 的 1440 条视频、2160 对人工偏好和原有聚合 repair 结果；本次已全部找到并复用。

背景构造的瓶颈主要是类别支持和建库门槛：现有 SegFormer/ADE20K 映射只支持官方 19 类主体中的 7 类。扩大到所有 72 个 prompt × 4 个生成器的 seed 0，共 288 条后，168 条因类别不支持拒收，另外还存在不可用 GrabCut 种子和掩码面积门槛。最终 34 条可构造。这些拒收反映建库管线的覆盖范围，不表示其余官方视频不存在或不值得评分；自然偏好实验不经过这些筛选。

三类数值需要区分：

- **原始视频分数**：origin 在 1440 条上的均值 0.8981；此前咖啡、吉他约 0.87–0.98，并不低。不同表示的余弦分数尺度不能直接比较成准确率。
- **背景干预绝对分差**：例如两条人工提示实验的均值 origin 0.014485、repair 0.005910，越小表示越稳定。这里的小数不是 repair 的原始得分。
- **人工偏好准确率**：由同一 prompt 下两条视频的相对排序与人类标签比较得到，才是下表的 58.53%/48.76%。高余弦值不保证正确排序。

## 分数为何下降：缺失帧与表示、聚合分开检查

29160 帧中，8109 帧没有得到目标主体掩码，占 27.81%；145 条视频所有帧均无掩码，178 条不足两个有效主体帧。这里是“检测结果为空”，不是经过人工确认的漏检率；生成视频确实缺少所述主体与检测失败尚未逐一分离。

`zero` 会把检测不到主体的帧所参与的相似度置零。例如 16 帧只检出 8 帧时，有效帧对占 28/120，即使这些主体表示完全相同，分数上限也约 0.233。这会把检测可用性强烈混入一致性分数。当前裁剪 zero 均值为 0.6159；exclude 的 1262 条条件均值为 0.9324，两者不可作为相同覆盖范围直接比较。

但缺失惩罚不能解释全部退化。两条视频都至少 90% 帧有掩码的 test 子集中，446 对偏好上 origin 57.40%、裁剪 zero 51.35%、裁剪 exclude 51.79%。**这里的 90% 是非空帧比例，不是轮廓准确率。** 该子集也经过检测覆盖条件筛选，只作机制诊断。

按照用户粗定位即可的要求，后续不围绕边缘精度反复筛数据。两条可视例子确有身体局部遗漏和少量背景混入，但没有把这些细节单独作为方法失败的充分解释，更没有据此删除分数不利的样本。

本次额外完成了[开发集聚合诊断脚本](https://github.com/winbeau/vbench-faithful/blob/89396909927e22ee00291ed562ae344a7a2a3ad1/scripts/counterfactual/diagnose_subject_aggregation_dev.py)：保留所有已有掩码和表示，改为 `0.5 × 相邻帧均值 + 0.5 × 全局帧对均值`。只读取 dev 580 条/870 对，新公式不在已经暴露的 test 上选优；这些是事后开发诊断，平局容差固定为零。

## 背景干预：288 条候选

[背景清单](../../configs/subject-repair/background288_manifest.jsonl)覆盖全部 72 个 prompt × 4 个生成器的 seed 0，无图像或分数挑选。[单独协议](../../configs/subject-repair/background288_protocol.json)沿用完整背景补集糊化，保留四个时间位置：整段、开头、中间、结尾。每个基底含 clean 和 8 个干预版本。

构造结果：34/288 通过自动门槛，254/288 拒收；通过部分覆盖 20 个 prompt、7 类主体和全部 4 个生成器，共 306 个实际评分视频版本、714 个 clean 帧。类别分布为 person 12、car 6、bicycle 6、boat 4、airplane 4、truck 1、bus 1。拒收原因允许重叠：类别不支持 168、GrabCut 种子不可用 63、面积小于 1% 为 67、大于 50% 为 25。自动门槛并非用户逐条确认的掩码真值。

全部 34 条的 9 个版本、8 个方法列已运行完成，共 2448 个分数单元；没有运行异常。`exclude` 在证据不足时保留未定义状态。254 个构造拒收仍保留在总候选分母，未用“无分数”填成背景变化为零。5712 个实际腐化帧通过像素重放，构造指定的编辑区之外改变像素为 0。34 条 clean 的所有成功方法分数与自然视频运行精确相等，进一步排除了 PNG/视频入口不一致。

## 实现复核与可复现产物

本次修复了一个真实预处理差异：锁定 VBench 的 `load_video` 实际返回 float32、数值范围仍为 0–255；旧 PNG 诊断曾在 uint8 上先 Resize，再转 float，产生额外舍入。现在统一在 DINO Resize 前转 float32。未归一化 RGB 的整数性、范围、NaN 和张量形状均检查；图像干预仍在精确字节像素上进行。

- 重评分 origin 与冻结 E0：1440/1440 的绝对误差小于 1e-6，最大 1.79e-7。
- 原有聚合 repair 与冻结历史 predictions：1440/1440 小于 1e-6，最大 1.49e-7。
- 咖啡、吉他的人工提示实验也已按官方浮点预处理重放，18 份评分掩码哈希不变；裁剪分数不变，origin 及其他表示列已更新。原始旧运行保留。
- 全量自然视频在 H100 物理卡 2–5 完成，4 卡墙钟约 747 秒。DINO/MobileSAM 严格确定性推理；Mask R-CNN 框前向使用原生 CUDA ROIAlign，三类 smoke 的重复掩码和分数重放一致，未承诺所有检测器 CUDA 核均严格确定。
- 背景构造改为按独立基底使用 CPU worker 并行，像素、掩码、算子与 PNG 设置均未改变。单/双 worker 的完整产物哈希与逐像素重放测试一致；150 个已完成 manifest 复用，中断中的一个片段另存归档，余下 138 条并行完成。
