# Subject repair：背景干预稳定性与定位补漏

2026-09-20。用户要求以“主体不变、背景变化时 repair 稳定，而 origin 明显变化”为主要目标；人类排序保留为辅助诊断。新目标已替换旧 Background goal 并设为 active，见[执行计划](../plans/2026-09-20-subject-stability-goal.md)。**v5 在完整 34 条开发集达到预定均值目标；同一批 60 条后续视频经构造恢复及尺寸归一化后，repair 变化降至 0.006353，主体干预 60/60 降分，但 Origin 为 0.080759，联合目标仍未通过。**

## 主条件与分母

主条件在运行前固定为开头四分之一背景高斯糊化，保留主体掩码内原始像素；中间、结尾和整段糊化均作为对照。Origin 使用锁定 VBench 的整帧 DINO、相邻项与首帧项。首帧受背景干预会影响后续全部首帧比较，因此开头条件比整段一致糊化更易暴露背景依赖；这不意味着所有时间位置都应下降 0.1。

目标是同一完整可评分队列上 Origin 平均绝对分差至少 0.10、repair 至多 0.01。逐条联合成功另报（Origin 分差 ≥0.10 且 repair ≤0.01），不能由均值代替。全空或不足两帧不记成功零变化，保留覆盖、缺失和所有构造拒收。原有 288 候选中的 34 个可构造基底全部保留：20 个 prompt、4 个生成器，9 个版本/基底，714 个 clean 帧、6,426 个实际版本帧。此集合已经参与开发。

构造仍用 SegFormer + GrabCut；评分用独立 Mask R-CNN + MobileSAM。评分只读取当前实际版本及官方 subject_en，不读取构造掩码，也不借用 clean 版本的框或特征。表示保留原成功案例采用的编码前主体隔离、RGB 128 填充、10% 边距裁剪、DINO patch 池化与全帧对聚合。没有改用偏好驱动的 CLS 候选，没有训练新 head。

## 单例诊断

`v_223dffdfd43f07ff254e` 是船减速片段，首帧只在右侧露出一部分蓝白船身，其余是水面和尾流。全空检测不能解释为视频空白。v3 clean 只检出 1/16 帧；v4 补齐到 16/16，首帧粗掩码覆盖右侧可见船身，面积约 19.64%。这是实际帧与模型掩码的目视观察，没有人工 IoU 真值。原片、掩码和观察记录保存在本地 control 目录；按用户要求逐例、低频查看，没有批量快速看图。

## 后续分组验证

新的 [160 条候选清单](../../configs/subject-repair/stability_followup160_manifest.jsonl)在构造与新分数产生前冻结：排除已明确用于主体干预开发的 62 个 prompt 后，剩余 10 组、4 个生成器、seed 1–4。现有 ADE20K 的 animal 与 minibike 类接入同一 SegFormer + GrabCut 管线；不下载新模型。animal 是泛动物标签，不能声称模型逐物种验证；train 仍不支持，16 条相关拒收留在分母。

这些自然视频此前参与过自然偏好评分，所有 prompt 的 seed 0 也曾尝试构造。所以称为“分组后续验证”，不称作完全未见的独立自然测试集。构造保留原 1%–50% 门槛、全部时窗及失败；不按 Origin/repair 分数选材。CPU 8 worker 用时 389 秒，60/160 通过数值门槛（大象 14、斑马 29、奶牛 5、卡车 9、摩托车 3），100 条拒收保留。

评分前按每类最小 UID 抽查首帧、逐例低频查看：大象和卡车实际背景糊化合理，摩托车粗掩码合理；奶牛例子却遗漏下半身和头部，实际背景编辑改变了大量主体像素。此问题超出小边界误差，已记为构造失败证据。数值门槛通过不等于语义主体完整保留，不能把全部 60 条直接称为合格的纯背景干预确认集；后续全量仍保留，作为包含构造错误的压力诊断单独报告。

### 构造恢复与尺寸归一化：另行冻结的后续诊断

第一例奶牛的旧 GrabCut 把初始语义区域以外约五像素之外固定为背景，无法补回大块身体。仅使用该例原图和原构造掩码的单帧诊断，把不确定区扩到各连通域框、每侧增加最长边 25%，主躯干和头部得到明显恢复（面积由 8.72% 到 18.49%）。该诊断没有读取后续评分。

据此冻结 recovery v2，在全部同样 160 输入上复用原 SegFormer 掩码，运行第二遍 GrabCut。数值合格数却从 60 降到 35，因为可选恢复的种子不足也被转换成空掩码；另有面积过大的例子。35 个构造的 5,160 干预帧通过像素重放，**此版本没有再评分**，负构造结果保留。随后单独冻结 recovery v3：若原掩码已经满足原面积门槛，而可选恢复失败或越过门槛，则保留原掩码并逐帧记录 fallback，不制造新的空掩码。v3 已完成构造与评分，评分仍冻结为同一个 v5。

此外，旧固定原生像素 sigma 带来分辨率强度差异：非人物视频在 256/480/512 短边上，经 224 短边评分变换后的名义 sigma 分别为 10.5/5.6/5.25。新后续集的分辨率构成为 20/13/27 条，start Origin 均值分别为 0.110168/0.066483/0.063866。这里也混有生成器和内容差异，不能据分组相关性直接归因。

新的[尺寸归一化构造协议](../../configs/subject-repair/protocol_resolution_normalized_v3.json)明确设定 `sigma = (person ? 18 : 12) × min(H,W)/256`，保留原 256 像素强度，所有基底使用同一规则。配合 recovery v3 在同样 160 输入上构造，全部四时窗、主体对照和失败仍保留，禁止按分数选视频。这是查看旧后续统计之后的机制诊断，不能重新包装成未暴露的确认集；原 fixed-pixel 结果保持不变。构造区域和相对强度同时改变，因此不能把新旧差异单独归因于其中一项。

recovery v3 数值合格 61 条、拒收 99 条，原 60 条全部保留。唯一新增的卡车 `v_4f8abc7bb931501fb862` 在最小掩码帧 26 上目视明显错误：只保留驾驶室一小条，却糊掉大部分主体。这个输入问题已在新评分前写入[冻结评分协议](../../configs/subject-repair/stability_followup160_normalized_scoring_v5.json)和[观察记录](subject_stability_20260920/normalized_input_observations.json)。61 条全部评分，数值队列完整报告；主分析为原来同样 60 条，新增卡车保留为已知构造失败，不能按新分数再改变名单。

奶牛新的实际糊化预览已确认补回主躯干和大部分头部/下半身，仍没有把单帧检查写成人工轮廓真值。一次显示一例的本地查看页为 `output/subject-repair/subject-stability-followup160-review-20260920/review.html`；新图在 `subject-stability-followup160-normalized-review-20260920/`。按用户要求低频、逐例查看。
