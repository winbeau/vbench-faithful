## 1. 目标与范围

针对 VBench 的 Spatial Relationship、Human Action、Scene、Multiple Objects 四维，修复 prompt 解析、标签对齐及字符串匹配导致的错误或 fallback。不能把视觉模型漏检、误分类、错误 caption 都归因于字符串匹配，也不承诺文本微调能修复视觉证据错误。

核心目标是减少误判，而不是人为拉开分数或保证 Repair 优于 Official。

## 2. 已确定的模型组织

- 最新决定：训练两个模型系统，替代此前四维共用一个 backbone 的方案。
- 模型 A：Scene 独立训练、部署，输入完整 prompt 和单帧 Tag2Text caption，输出三个标签之一。
- 模型 B：Spatial、Human Action、Multiple Objects 共享 backbone，各自训练一个 LoRA adapter；输入仅为 prompt，输出各维度简洁 JSON。
- 模型 B 按已指定的维度进行 head/任务硬路由，实现上激活对应 LoRA adapter；不让 LLM 选择维度，不要求额外增加神经分类 head，不将三个 adapter 默认叠加激活。
- 两个系统不共享训练中的 adapter 参数；Scene 是否采用 LoRA 或分类头、是否与模型 B 使用同一基模型号尚待确认。
- 不训练四份独立完整模型，不默认引入直接看视频的端到端模型。
- Qwen3-8B 是当前建议起点，具体模型版本、LoRA 配置和训练预算尚未最终确认。

## 3. 四维分工与最小输出

最终讨论收敛为：三个维度前置编译，Scene 末端证据判别。撤销此前“每个 adapter 都必须同时训练 compile/match”的设计。

| 维度 | 小模型职责 | 确定性后端职责 |
| --- | --- | --- |
| Spatial Relationship | 抽取多个有序关系三元组，对象名称对齐后端可用标签 | 检测实例绑定、几何关系判断及聚合 |
| Human Action | 将 prompt 中动作解析为 Kinetics-400 标准类别 | 读取 UMT 类别证据，按已定义规则评分 |
| Scene | 判断 Tag2Text caption 是否支持目标场景 | 聚合逐帧判别结果 |
| Multiple Objects | 提取完整目标对象集合，支持超过两个对象，对齐后端标签 | 判断各目标是否同帧出现及聚合 |

### 3.1 Spatial Relationship

```json
{
  "relationships": [
    {"subject": "cat", "relation": "left", "object": "dog"},
    {"subject": "dog", "relation": "below", "object": "bird"}
  ]
}
```

- 支持多个三元组，保留主客体顺序。
- 关系输出限于后端实际支持的集合；不得将不支持的关系强改成支持的关系。
- 无额外 LLM match 阶段；对象标签对齐后交由算法处理。
- 多三元组的组合评分规则尚未确定，不能声称已有实现支持任意关系图。
- 同类多实例、颜色等身份约束不能靠类别名完全解决；其表示和不支持处理待定，不允许静默丢失后宣称完整满足。

### 3.2 Human Action

```json
{"actions": ["playing guitar"]}
```

- 输出名称须来自锁定上游的 Kinetics-400 类别文件，不能随意使用其他版本的类别或编造 ID。
- 无额外 LLM match 阶段，直接按标准类别读取 UMT 输出。
- “Top-5 命中”是评分机制问题，LoRA 标签解析不会自动修复它；采用目标概率、校准阈值或其他规则需独立确定、验证。
- 主要动作选择、多动作聚合、K400 外动作及歧义的处理尚待定义；不得强行映射到最近类别。

### 3.3 Scene

输入：

```json
{"prompt": "A person walks on a beach.", "caption": "People walking along a sandy seashore."}
```

输出为单个分类标签，不要求 JSON 包装：

```text
supported
```

允许值：`supported`、`contradicted`、`insufficient`；每个输入对输出一个标签，不是同时输出三个标签。

- 不设独立 compile 阶段。输入必须是原始完整 prompt 和单帧 Tag2Text caption，不要求调用方额外提供或抽取目标场景。模型只判断 prompt 中的场景要求。
- Scene 是“指定场景是否生成成功”，不是完整 prompt 与 caption 的泛化相似度，不混入动作、画质等要求。
- 用户上传的 VBench 1.0 论文（arXiv:2311.17982v1，第18–19页）明确以 ocean 与 river 的区别说明场景要求；原方法检查场景相关词出现在 caption 中，并汇总成功帧比例。
- 同义表达可支持目标，但相近场景、宽泛描述不能自动判成立。例如 ocean 对 open sea 可支持，对仅有 a body of water 应为证据不足。
- 不输出模型口述的任意连续分数。最小修复候选口径为 supported 记1，其余记0，另报证据不足率；正式采用前仍需验证。
- 若自然视频大多正确生成场景，高分可能来自任务天花板，不能为了区分度人为扣分。
- 先人工抽样估计真实成功率及错误来源，再判断微调价值。相近错误场景挑战集只验证判别能力，不能代替自然集收益。
- caption 本身误报场景时，纯文本判别不能保证恢复视频真值。

### 3.4 Multiple Objects

```json
{"entities": ["cat", "dog", "bird"]}
```

- 衡量要求的多个对象是否在同一帧共同出现，不是视频中所有物体的总数。
- 目标集合不限于两个对象，不能仅按 `and` 字符串切分；应完整提取评测要求中的对象。
- 无额外 LLM match 阶段。对象名称对齐后，由检测及集合匹配算法完成核验。
- 当前最小 schema 不要求 `count`。验证“两只狗”等实例数量是另一个扩展问题，不应混称为原有对象共同出现指标。
- 额外对象不自动扣分；猫狗分别出现在不同时段，不等于同帧共同出现。
- 仓库当前 Official 适配对目标数存在恰好两个的校验。支持更多对象属于修复/扩展后端能力，不能静默改动 Official 或称为官方原样实现。
- 对多于两个目标，全部同帧出现比例是自然扩展候选；是否同时报告部分覆盖率及采用何种主分数尚待确定。

## 4. 数据与标注约束

- Human Action 标签对齐实际锁定的 K400 词表；对象标签对齐实际使用的 GRiT 输出及版本。
- GRiT 观测标签目录不能未经核实当作穷尽的固定词表；未知类别需显式处理。
- 三个前置解析任务的样本输入仅为原始 prompt；维度由外部硬路由指定，冻结词表用于训练标注和输出校验，不要求样本额外输入评测元数据或视觉证据。不能根据该视频检测到什么反向修改目标。
- pipeline 输出是输入证据，不自动作为正确标注。不能用旧字符串规则批量生成真值后宣称修复了该规则。
- 保留语义差别：同义不等于上下位关系；未提及不等于不存在；未检测到不等于实际不存在。
- 训练数据应包含自然改写、相近类别、否定、主客体交换、多个关系和多对象枚举等困难样本。
- 同源 prompt 的改写、同一视频的帧及派生样本不得跨训练和测试集；先划分再扩写。
- 测试标注独立人工审核，建议双人标注及分歧仲裁。具体数据量和标注流程待定。
- Spatial、Human Action、Multiple Objects 输出简洁 JSON；Scene 输出单个三分类标签。不引入复杂通用证据图、自由生成解释或主观置信度字段。

## 5. 验证与论文约束

- 同时评估接口准确性和最终视频评分，不只看训练 loss、JSON 合法率或少量示例。
- 至少比较旧规则、简单规范化规则、同基模未微调与 LoRA 微调。
- 将解析改动与评分公式改动分开消融，尤其 Human Action 的 Top-5 替换及多对象聚合。
- 分维度报告解析/匹配错误、fallback 或不支持比例、覆盖率、自然集人工一致性与运行成本。
- 不支持及失败不得通过删除样本抬高分数；定义并固定分母。
- 按源 prompt/视频分组统计不确定性，不把相关帧当独立样本。
- 当前没有训练结果或真实模型验证，不能宣称 Scene 独立加三 adapter 的架构优于其他方案，也不能宣称语义修复已改善自然偏好一致性。
