## 3. 数据构造与规模

主体定位按用户要求以“大体约 80% 分辨出主体”为工作标准；这不是已测得的 IoU。
小块漏分、边界不准或少量背景混入不再触发反复人工审核；明显找错主体、整段无定位等失败仍需计数。

- 主条件：逐帧在主体掩码内施加 Gaussian blur，背景像素逐位保持不变。
  不使用镜像盒，也不要求主体区域与背景区域等面积。
- 全片主体糊化为主实验；start/middle/end 局部时窗分别作为位置控制。
  补充背景时序破坏作为敏感性对照，构造方式和解释在评分前固定。
- 复用现有 `region_discrimination` 构造、无损 PNG、manifest、哈希与像素自证设施。
  现有 288 条 subject 候选中的 34 条已构造基底可用于接通和诊断；明确标注其来源，
  不将它们称为官方 background 维度样本或独立未见测试集。
- 正式实验应覆盖 h100-server 上可用的官方 background 输入，先清点全量，按 source prompt
  分组冻结清单与开发/测试划分。扩大候选覆盖，不停留在两条示例或原有七条。
  含明确主体的视频用于主干预；无明确主体的视频保留为覆盖统计或预先定义的控制。
- 完整保存输入总数、支持数、构造失败、评分失败、拒收原因与逐视频结果。
  不按 origin/repair 分数是否符合预期选择基底。

## 4. Repair 与复用边界

分开测量官方整帧 origin、只改变时间聚合的对照，以及抑制主体后的背景表示 repair。
若聚合对照尚未实现，作为本轮新增消融，不称为已有 background 修复结果。

优先复用 subject 实验中已验证的构造、运行、统计与模型装载能力，但以 background 为目标：
评分背景区域由**独立评分定位得到的主体掩码的补集**确定；构造用的掩码不得直接供 repair 评分。
编码前抑制主体、背景 token 池化等候选只能在开发集比较，正式测试前冻结方法和参数。
保持 CLIP 官方基线独立可核验，不将更换编码器的收益混同于分离背景或聚合方式的收益。

每个实际干预版本独立定位和评分；仅在像素内容、方法与资产哈希一致时复用已有评分缓存。
不得将干净片段的评分掩码直接传播给所有干预版本以制造不变性。
定位缺失、背景证据不足及异常帧处理需先固定，并同时报告端到端覆盖和条件化诊断。
不得用主体裁剪的几何方式截掉待评估的背景。

metric 包之间不互相导入；确有共用的模型适配放在 `packages/audit-models/`，
评分公式留在各自 metric。优先使用已有权重与实现。
若确需 Qwen 8B 的 LoRA/head，尽量复用 spatial、multiple objects、human action 的训练设施、
MovieGen 和已用训练提示词；另行冻结训练数据、版本与分组划分。
没有人工审核的语义标签子集时，不宣称语义 head 准确率；该可选分支不阻塞主体糊化实验。

## 5. 统计与预期解释

对每个后端、每个位置分别报告：干净分数、干预后分数、带符号变化
`score(edited) - score(clean)`、逐视频绝对变化及其均值/中位数。
同时报告 repair 相对 origin 的配对变化缩减，以 source prompt 为聚类单位估计置信区间。
不能只看总体平均分差，因为升分与降分可能互相抵消。

主体糊化属于 background 的非目标干预，理想 repair 应基本稳定。
origin 是否受影响、上升还是下降由实际实验决定，不强制要求 origin 降分。
全片一致地糊化某一区域不必然造成时序不一致；背景敏感性结论应来自明确定义的
背景时序破坏对照，不能把“更糊”直接当作“一致性更低”。

独立自然集报告 background 的人工偏好准确率、覆盖率、失败分母、平局规则和配对区间。
数值验收阈值、非劣界限、主统计量和失败处理规则应在查看正式测试结果前写入冻结协议。
本文件是工作目标，不冒充已完成的参数预注册或实测证据。
