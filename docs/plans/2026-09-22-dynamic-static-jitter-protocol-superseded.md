# Goal：Dynamic Degree 静态视频像素震颤反事实与 Repair

日期：2026-09-22。工作分支：`winbeau`。

本文为用户已授权实际执行的目标。当前进入开发实现与 pilot 验证，独立测试尚未冻结或运行；进展和失败记录见[运行报告](../counterfactual-reports/dynamic_static_jitter.md)。下文数值是预定工程验收标准，不是已有结果或用户指定的阈值。

## 1. 最终目标

实现一套可复现的“静态视频 → 像素震颤”反事实构造与 Dynamic Degree Repair：静态视频加入非运动干扰后，Repair 仍保持低分，分数几乎不变或降低；真实运动增强时，Repair 保持实质性的升分响应。

首选路线为“预训练模型估计运动轨迹 + 算法验证轨迹并计算运动程度”。成功须同时满足数据构造有效、静态干扰不抬分、真实运动响应保留、实际评分覆盖和可复现交付，不能仅由均值下降判定。

用户接受静态反事实降分，所以主合同为单侧不抬分：`S_cf − S_base ≤ ε`。另报 `|S_cf − S_base|`，只有绝对变化也小才称为严格不变性；明显下降单列为抑制响应。

## 2. 反事实数据构造

### 静态主实验

从真实视频按预先固定规则抽取一帧，重复成静态片段。源图身份和结构位置恒定，原生运动为零。以这一静态片段作为所有干预的共同 base，而非直接把原运动视频视为静态。

| 族 | 干预 | 预期 |
|---|---|---|
| 像素震颤（主族） | 各帧独立的有界亮度／颜色扰动；增加局部空间相关的噪声版本 | 静态低分，干扰加重不应系统性抬分 |
| 频闪 | 全局及固定局部区域的亮度变化；交替、随机变化分别报告 | 静态低分，不能只对一种交替模式有效 |
| 编码控制 | 同一静态片段经过完全相同的编码流程，无额外干预 | 检查编码本身引入的变化 |

每族至少包含无、弱、中、强四档，噪声采用多个预定随机种子。全部版本保持帧数、时间戳、分辨率、时长与编码设置一致。保存编码前重放证据与实际解码验证，确认干扰未被编码或评分预处理消除。

主族只改变外观数值，不改变像素坐标。整帧平移、相机抖动、对象位移不冒充零运动；局部几何扰动如需研究，另列探索条件并先确认其语义。强干预仍须保留可辨认结构；过曝、全黑或结构被噪声淹没记为构造拒收或超范围压力测试。

增强构造先在开发集完成：依据干预实际强度、可见性和结构保留确定剂量。允许用开发集诊断 Origin 的错误响应，但独立测试的基底、强度和种子在评分前全部冻结。不得只保留 Origin 高分或 Repair 低分的例子；Origin 未被误导也是应保留的结果。

### 真实运动控制

以匹配的纹理、背景和主体面积构造已知位移轨迹，设置静止以及慢、中、快三档运动；保持 FPS 与时长固定，在无边界穿越、无遮挡变化的有效范围内比较速度。几何轨迹仅作为构造真值，不输入评分器。

各运动等级再加入与静态组一致的外观干扰，验证真实运动未被一并压低。保留真实往返运动／振动案例，避免把方向反转当成伪运动。自然运动视频另作外部有效性检查，不能用合成阶梯替代自然验证。

### 划分与审计

按源视频和 prompt family 分组划分开发集、独立测试集；同源不同帧、不同生成器的同 prompt、不同剂量及种子不得跨组泄漏。已看过的样本只可作开发或明确标注的复测。

正式测试目标至少 100 个源视频基底，覆盖可用生成器与不同纹理复杂度，并单列独立 prompt 组数；如果实际资格不足，保留完整候选分母并报告覆盖限制。先冻结来源清单，再冻结通过输入质量检查的分析清单；质量判定不读取新评分。

## 3. Repair 实现

```text
当前视频与时间戳
  → 固定物理时间采样、固定空间网格
  → 预训练多帧点跟踪模型：轨迹、可见性、置信信息
  → 局部结构匹配、双向一致性、移动与静止解释比较
  → 排除定位噪声，累计有证据支持的位移／时间
  → 固定空间与时间权重汇总运动量
  → 分数 + 有效覆盖 + 失败／证据不足状态
```

- 优先评估已有本地点跟踪权重，例如 CoTracker3；记录模型、checkpoint 哈希与实际接口。模型选择、匹配特征和阈值只在开发集比较，独立测试前冻结。
- 比较同位置匹配与移动后匹配；仅接受有可靠对应关系支持的位移。静止且匹配可靠的点是有效零运动证据，不是缺失。
- 噪声容限来自独立静态开发样本的定位误差；不能仅靠平滑轨迹、删除高频运动或惩罚方向反转获得稳定性。
- 评分端独立处理每一个视频，不读取 clean 对照、干预标签、噪声种子、构造轨迹、掩码或同组其他版本；修改文件名不应改变结果。
- 原始量保留位移／图像尺寸／秒等明确单位。聚合不能只选最大的几个异常点，也不能因有效点减少而放大剩余点权重。报告有效面积和时长；证据不足不得伪装成静态零分。
- 新方法先接为独立候选变体，经过真实 CLI 与实验脚本 parity 验证后再决定是否成为默认。不得把现有历史分数重新标为新方法结果。

## 4. 预定验收

为避免通过缩小输出尺度获得假稳定，定义 `R` 为冻结的“干净、中等真实运动”开发集分数中位数，要求 `R > 0` 且真实运动排序有效。冻结后使用 `ε = 0.05 × R`。该比例是本目标的工程提案，不沿用其他维度的绝对分数门槛；正式独立评分前须将最终数值及来源写入版本化协议。更换模型或分数定义须重新冻结开发标定，不能在已暴露测试集上反复试验。

| 项目 | 验收要求 |
|---|---|
| 静态绝对低分 | clean 与合法震颤版本均接近零；每一主要干预族中至少 95% 测试基底的最坏版本分数 `≤ ε` |
| 单侧不抬分 | 每个基底先取所有剂量／种子的最坏正增量；每族至少 95% 基底满足 `max(0, S_cf − S_base) ≤ ε`，且最坏正增量均值的 95% CI 上界 `≤ ε` |
| 真实运动敏感性 | 静止及慢／中／快三档运动的相邻严格排序准确率 `≥ 90%`；测试中等运动的 clean 分数中位数 `≥ 0.8R`，防止恒零或分数坍缩 |
| 干扰下响应保留 | 匹配中等运动组的干扰后均分／clean 均分 `≥ 0.8`，并保持运动阶梯相邻排序准确率 `≥ 90%`；同时报告分差，不能靠抬高所有受扰视频获得“保留” |
| 评分覆盖 | 每族、每个强度的有效评分覆盖 `≥ 95%`；候选数、构造拒收、评分失败和证据不足全部单列，缺失不得算通过 |

逐族、逐强度报告，不以合并均值掩盖强干预失败。置信区间按源／prompt family 聚类，不能把同源的种子与剂量当独立样本。通过率同时报告区间、完整分母、P95、最大值和失败案例。

Origin 使用锁定上游的真实官方布尔结果，报告静态误判率、`false → true` 翻转率及配对变化；光流幅度只作机制诊断，明确标注不是官方最终分数。Repair 报告连续分数与开发集冻结的动态判定阈值下的误判率；同一干预下与 Origin 比较误判率、覆盖和真实运动检出率，不直接比较不同量纲的分数大小。若 Origin 本来没有误判，应如实报告，不能宣称修复了本实验未观察到的错误。

## 5. 实施顺序与交付

1. 盘点 `winbeau` 的接口、现有本地模型和可用数据；实现可重放的静态构造及几何／时间／编码核验，先形成开发预览。
2. 接通候选 Repair、单视频与批量 CLI，完成有针对性的算法／合约测试和真实推理 smoke；冻结开发标定、独立测试清单及配置。
3. 进行独立 Origin／Repair 实测；消融至少比较原始轨迹量、加入对应验证、再加入噪声容限与完整聚合，确保效果不是仅由整体压低分数产生。
4. 交付构造配置和 manifest、可复现入口、逐视频与逐轨迹证据、统计与置信区间、可视化案例、数据流方法说明，以及 `base → 反事实` 表格。表格显式区分不抬分／严格不变性与真实运动敏感性。
5. 本目标只有在构造、Repair、响应控制、覆盖和独立验证共同达标时才算实现。失败保留原始结果，在开发集诊断；暴露过的测试集不得再次称作未见确认。
