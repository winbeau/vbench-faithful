## 旧行到底测了什么

`Origin 0.4142 → 0.0277 / Repair 0.3983 → 0.0178` 是冻结 980 视频中
**505 个完整 16 帧目标遮挡配对**的均值，并非 prompt 改写实验。
Repair 为固定 Objects v6 LoRA 加相邻同名框 IoU≥0.5 确认后端。

原始 49 种对象组合上，文本 adapter 与官方目标解析一致；这批实验没有证明
LoRA 修好了 `and` 解析。分数差异主要来自视觉检测与后端时序过滤。
两方法在目标真正消失时都应该降分，**Origin 下降本身不是缺陷**。

[当前 v2 结果与代价](semantic-models/docs/deterministic/objects-repair-v2/README.md)。

## 需要修正的实验解释

1. **构造完整不等于语义有效。** 980 中 475 个几何构造不完整；505 个完成模型复核的
   端点中，275 个被判为目标全帧不可见，仅 142 个还满足原片两对象可见、CF 另一对象
   仍可见的严格隔离条件。复核为同一视觉模型多遍共识，`human_reviewed=false`。
2. **灰块遮挡可能有附带影响。** 剩余目标部位、其他物体受损及上下文变化都有记录；
   重度等面积背景对照两端完整仅 25/980 个视频。505 组总降分不能直接归为正确敏感性。
3. **文本问题和视觉问题不能互相替代。** LoRA 是文本解析器；相邻框确认改善孤立
   误报属于后端规则的作用。该后端还损失短暂可见目标，不能只报 CF 更低。

旧表的数值本身能从冻结证据复算；问题在于把这行当成“干净构造”或“LoRA 文本收益”。
历史表、失败项和原视频保留，不根据是否有利于 Repair 改选样本或改分数。

## 官方接口事实

固定上游 `VBench@fd18b3d` 的 `multiple_objects.py` 实际执行：

```python
object_info = info['auxiliary_info']['object']
key_a, key_b = object_info.split(' and ')
```

因此这里拆的是预设辅助对象字符串，**不是运行时从完整 prompt 提取前两个对象**。
多于一个分隔符会导致 unpack 异常，而不是自动忽略后续项。仅改写 prompt、保持
规范的辅助目标不变时，Origin 按设计不受影响。不能故意破坏辅助字段、把异常记成 0，
再宣称发现了官方视频评分的语义失效。

## 两个不同的修正方向

- **文本不变性（适合检验 LoRA 解析）：** 视频与要求的对象集合不变，作语义等价的
  列举顺序或连接结构改写；冻结改写表与对象集合，先检查是否引入新对象、动作或关系
  要求。Origin 保持合法官方辅助目标，错误/域外输入保留失败；分别报告 LoRA 集合
  解析一致性、最终评分及词面辅助接口压力测试，不保证 Origin 必然降分。
- **视觉敏感性（修正现有遮挡构造）：** 使用独立定位/分割与逐帧目标身份确认，只移除
  指定目标、保护其他目标；在评分前审核原始共现、目标消失、其他目标保留和完整
  16 帧，并配同面积背景控制。未通过者留在候选分母，不将缺帧算零或根据评分挑选。

当前用户尚未确认要替换实验命题还是修复原遮挡构造，故未启动新训练、批量构造或评分。
在明确选择前，这行应标为**历史遮挡诊断**，不作为新的文本不变性结果。
