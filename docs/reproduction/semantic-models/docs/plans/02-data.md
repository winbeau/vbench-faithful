# P1：数据收集与标注

已获授权进入原料下载与检查；本轮仅获取文本/标注，不下载媒体或权重，不调用teacher、不训练。实际数量与许可见 [数据盘点](../data/README.md)，不能将原始条数直接作为可训练样本数。

| 任务 | 候选 | 加工与风险 |
| --- | --- | --- |
| Spatial | Visual Genome区域描述及关系 | 筛支持的关系；自然文本必须覆盖输出三元组，不能用全图关系标注局部描述 |
| Objects | Flickr30k Entities实体短语、VG | 提取prompt实际提及的对象，不标入图中存在但未提及的对象；核验GRiT标签映射 |
| Action | 锁定K400类别表 | 先建立400类覆盖；规则改写只能作弱监督，不假称大量独立自然表达 |
| Scene | 独立prompt及真实Tag2Text输出；SNLI辅助 | SNLI非场景专用，不冒充真实pipeline三分类标签 |
| 多任务prompt候选 | 官方MovieGenBench | 用户希望未来纳入训练；原数据为评测prompt，无本项目目标标签。遵守非商业许可，先定义来源划分；使用过的prompt不得再充当独立MovieGen测试 |

## 原料审计

记录URL、许可证、版本、下载哈希、原始条数、过滤原因、去重条数、可用条数及来源ID。先下载标注文件，不自动下载大规模图片/视频或模型。

## 划分与质量

1. 先按源prompt、图像/视频和派生家族划分，再构造改写、模板或负例。还要跨数据集去重：SNLI来源涉及Flickr30k，不能各自随机划分后默认互不泄漏；保留原始来源ID，缺失时用文本重复/近重复检查作为补充而非完整保证。
2. 现有VBench最终测试及已反复调参的审计集不作为新训练来源。
3. 按JSON/schema、K400词表、关系方向、实体提及、标签证据校验。
4. 三分类区分支持、矛盾和不足；未提及不等于不存在。
5. 小批人工复核后才扩量，记录各任务噪声和覆盖。
6. teacher仅在原料缺口明确且另行授权后使用；独立测试金标准人工标注，不能只凭teacher一致。

## 候选预算（非硬性目标）

Spatial 3k、Action 10k、Objects 3k、Scene 4k训练样本；独立dev/test另计。按500/2k/完整数据学习曲线决定是否扩量。Action的400类覆盖与Scene真实caption难例优先于重复模板数量。

## 门禁

许可证可用、来源与split可追溯、金标准独立、schema和未知情况规则确定，才进入P2。数据落在忽略目录，Git仅存manifest格式、处理脚本、统计与合成测试fixture。
