# 下一阶段行动指南：可信评测、四维确定性实验与模型交付

## 1. 目标与当前判断

下一阶段不是继续追逐某个开发集的 0.97，而是回答：**在同一批原始视频、同一视觉证据与公平判据下，Repair 是否比 Origin 更符合明确的语义要求？**

现有四维 adapter、训练入口、曲线工具可以复用，但训练完成不等于研究验收完成。既往报告中的 F1、端到端 VBench 分数、蜕变一致率是三类不同指标，不得合并解释。LLM 两遍标注与仲裁仍是模型标签，不称人工金标准。

本指南仅规划下一阶段；未在本轮启动新训练、付费标注或重算冻结结果。

## 2. P0：先修评测与数据审计（最高优先级）

### 2.1 已从代码确认的 Scene 记分卡问题

`script/` 的实际路径为 `scripts/score_scene_metamorphic.py`。本轮已阅读该文件，确认：

1. `build_conditions()` 用 `meta.pair_type` 充当 `expected`，而不是已标注的 `target`。同源视频不一定生成成功，错配视频也不保证视觉矛盾；构造意图不能替代真值。
2. 所有 synonym 行被硬设为 `supported`。同义关系只能推出两次判断应一致，不能推出原视频符合要求。原图失败时，稳定的负判定也可能正确。
3. `official_label()` 对完整 prompt 分词匹配，并把非匹配映射成 contradicted。这不是经 parity 验证的完整官方 scene 入口；官方使用 `auxiliary_info.scene`，非匹配也不必然表示矛盾。
4. Official 没有 insufficient 分类；用三分类准确率强行比较，会结构性地给它记零，不能据此声称 Repair 胜出。
5. 主分数按条件平均，当前 CI 却对所有样本的正确率做普通 bootstrap；估计量不一致，也没有按来源家族重采样。
6. 缺失 Repair 输出被排除在部分分母之外，可能抬高成绩。

**处理：保留旧文件和运行产物作为历史记录，将 0.319 vs 0.799 等结果标为探索性、待协议修正重算；暂不作论文主表。**

### 2.2 必须完成的其他审计

- 生成 manifest：代码提交、dirty diff、模型/adapter/tokenizer 哈希、数据哈希、训练/验证/测试身份、来源视频与 prompt 家族。
- 查重不只看 `sample_id`：检查原始 prompt、近重复、图像/视频 ID、跨配对两端来源、长短改写家族。多个版本的同一 seed 不得计为独立家族。
- Scene 的不同帧不能跨 split；cross-pair 的 prompt 和证据视频都必须留在同一 split。检查训练和测试是否复用了同一份 scene-less prompt 列表。
- 当前已多次查看的 dev/test 转为开发集；正式盲测重新冻结，不能继续按其错例修标签并宣称独立提升。
- 检查 canonicalization：不能把通用词干算法当实体规范化；避免 ceiling→ceil、lens→len、airplane→airplan。归一化保留原始提及、转换规则与映射依据。
- 检查 Scene 重复 ID：跨帧、跨配对、supported/contradicted 必须有明确唯一 ID；冲突记录不能被 `setdefault` 静默吞掉。
- API 任务必须逐项持久化、断点续跑、记录真实累计支出；避免失败后重跑整批、预算文件与内存上限不一致、并发写丢账。

**P0 验收：**新评测单测覆盖以上反例；所有结果保留失败分母；来源划分与计数报告可复验；用小批样本核对官方实现 parity 后，才进入主实验。

## 3. P1：冻结三层评测，禁止混表

| 层级 | 回答的问题 | 必须报告 |
| --- | --- | --- |
| 文本解析/分类 | 模型是否理解输入？ | Spatial 有序三元组集合 F1；Action K400 集合 F1 与 other 单列；Objects 规范实体集合 F1；Scene 三类 macro-F1、混淆矩阵、有效输出率 |
| 原始视频评分 | Origin/Repair 对同一原始视频怎样打分？ | 相同视频 UID、prompt、帧、权重、阈值与聚合下的官方分数、Repair 分数、覆盖率、配对差；高均分不等于更正确 |
| 确定性实验 | 必须变/必须不变时，评分是否守约？ | 每个变换族单独给出违约率、方向、配对差、家族数和 CI，敏感性/不变性分栏 |

基线至少包括：Origin、规则规范化修复、未微调同底座、LoRA Repair。前三解析任务尽量复用同一份视觉缓存，只替换文本接口；Scene 固定同一 Tag2Text caption。后端评分公式若改变，另列消融，不能归功于语义 adapter。

Scene 二分类可比口径：有明确场景条件时，比较 supported 与 not-supported；另给 caption 不足率。无场景要求时标记 N/A/弃权，独立报告 Repair 的 insufficient 行为，不作为强行击败官方的主指标。

## 4. P2：落实用户选定的四类确定性实验

### 4.1 Spatial：水平/垂直镜像——敏感性

仅选择清晰、可定位、非对称且满足原始关系的样本：水平翻转针对 left/right；垂直翻转针对 above/below。不要用普通 scene 视频清单充当 spatial 实验样本。

每个 base 构建四格：

| | 原 prompt P | 方向同步替换的 P′ |
| --- | --- | --- |
| 原视频 V | 应满足 | 应不满足 |
| 镜像视频 T(V) | 应不满足 | 应恢复满足 |

报告原条件掉分、同步改 prompt 后恢复程度、方向正确率；基例本身失败的样本保留并单列，不要求它继续大幅掉分。

先做**证据级**实验（框坐标确定性镜像）隔离文本/几何接口，再做**视频级**实验（镜像视频后重跑 GRiT），区分视觉检测不等变与接口错误。保持帧数/时长/编码参数一致；上下翻转的视觉异常单列。

### 4.2 Action：同义表达不变性 + 类别替换控制 + other 协议

**概念需分清：视频不变不代表分数必须不变。** 如果动作类别真的从 playing guitar 改成 swimming，匹配条件改变，属于条件敏感性控制，不能命名为不变性。

- 主不变性：同一 K400 类的表达改写，如 riding a bike→riding a bicycle；目标 ID 和评分应一致。
- 负对照：替换为另一动作类别；只有独立核验新动作确实未出现、且不是兼容多动作场景时，才期望评分下降。
- OOV：确认不属于 K400 后输出 other；这是开放集拒识/适用范围测试，单列拒识 precision/recall、错误强配率和覆盖率。不得映射为任意类别，也不能把 other 自动变成满分。
- K400 名称与 ID 全程锁定；别名规则冻结后对全部样本统一应用。多动作不能因为一个 other 就抹掉已识别类别。

### 4.3 Objects：occlusion-only 逐级遮挡——敏感性

复用 audit 的目标选择/遮挡逻辑，但写入新输出目录。先确定被遮挡对象身份和其他目标的可见性。

- 设定无遮挡及多个递增遮挡等级；配套等面积背景遮挡、非目标遮挡和无操作控制。
- **像素被遮挡不等于对象立刻不可识别**。部分遮挡不强制任意比例掉分；重度且经核验不可见的终点才有明确不满足预期。
- 对于全目标合取语义，完全缺失某目标应不满足；但连续官方分数是否归零取决于其公式，先做实现核验，不预设数值。
- 主报可见性终点方向正确率；单调性作为次指标，给出适用条件与容差；遮挡外像素校验、目标外检测变化单列。

### 4.4 Scene：场景词同义替换——不变性（优先主实验）

这是 Repair 最直接的价值验证，但同义表必须逐上下文审核：ocean/sea 在开放海面条件下通常可用；garden/yard、road/street、beach/seaside **不自动严格等价**，有争议对进入候选，不进入主表。

- 使用相同视频/帧/caption，仅替换场景表达；固定真实 scene requirement，而不是对完整长 prompt 生硬匹配。
- 原例支持与原例不支持两类均保留：预期是正确标签不变，不是全部 supported。
- 与明确不等价的场景词替换构成负对照（如 ocean/forest），且必须核验真实画面与文本证据。
- 主指标：**正确且一致率**（原句与同义句均判断正确的家族比例）；同时报告预测一致率、错误但一致率、配对评分差。
- 必须列出 always-supported、always-not-supported、复制原判定等常数/复制策略的结果，证明主指标不能靠不看内容刷高。

## 5. Scene 专项提升：先纠正训练目标，再加样本

目前 luna 看图给标签，而学生只看 prompt + Tag2Text caption。二者信息不对称：图片显示海洋、caption 只说 water 时，视觉 label 可能是 supported，但文本证据应是 insufficient。此类不可判定样本不能靠多训解决。

下一步每条 Scene 样本保留两组标签：

1. `visual_truth`：基于真实帧的场景是否成立；供端到端评价及错误归因。
2. `caption_evidence_label`：仅根据学生实际能看到的 prompt + caption 判三类；作为文本 Scene 模型监督目标。

分别统计 caption 幻觉、证据缺失、文本判别错误、格式失败。luna 仅辅助视觉标签；文本仲裁不能用学生看不到的图像推断 target。无条件跨场景配对、同源即支持、关键词缺失即不足都必须避免。

补数据优先覆盖：contradicted/insufficient 边界、宽泛/具体场景（water/ocean/river）、否定、无场景条件、真实 caption 错误。多帧扩样增加观测，不增加独立视频家族数；不能把 18 个场景 prompt 扩写成 100 个独立来源。

## 6. P3：受控训练与防过拟合

- 先冻结标签规范、数据版本和 train/dev/test 家族，后训练。训练前修标只基于统一规则与盲审，不参考哪种标签更有利于 Repair。
- 同一提交、相同训练预算比较旧/新数据；少量预先列出的超参数（学习率、dropout、步数）只用 dev 选择，保存 best-dev 和 final 两个 checkpoint。
- 绘制 train/dev loss、token accuracy、严格解析有效率及完整 dev 上的任务级指标。token accuracy 不当任务 F1；小切片 callback 不替代全 dev。
- 正式 test 只在模型与阈值冻结后跑一次；模型选择不看 test。若已用于反复诊断，转为开发集并另留未见测试。
- 0.97 是期望目标，不是验收造数要求。报告有效分母、困难样本和 CI，不缩小评测范围、不删除失败、不因没达到目标就改指标。

## 7. 建议执行顺序及停止门禁

| 顺序 | 工作 | 交付 | 完成条件 |
| --- | --- | --- | --- |
| 1 | 版本/数据/评分器审计 | `evaluation-audit.md`、问题清单、回归测试 | 旧指标口径澄清，标签/分母/CI/来源泄漏检查通过 |
| 2 | 冻结实验协议与清单 | `configs/experiments/`、变换 manifest、盲测清单 | 四维有效 MR、适用范围、阈值、分组均预先确定 |
| 3 | Scene 同义主实验小批验收 | 同义与负对照逐样本预测、Origin parity | 先 20–30 独立家族排错，再固定更大测试规模；不足就如实报告 |
| 4 | Spatial 镜像、Objects 遮挡 | 原视频与变换视频哈希、视觉缓存 | 变换有效性与非目标控制通过 |
| 5 | Action 不变性及 other 协议 | ID/别名表、OOV 测试、覆盖率 | 类别替换不混称不变性，拒识和匹配分开计数 |
| 6 | 四维原始数据双后端评分 | 四维同 UID Origin/Repair 分数表 | 没有漏项、原始/变换集不混，后端与公式差异披露 |
| 7 | 根据开发集修复与重训 | 冻结 adapter、曲线、消融报告 | 独立测试未泄漏，不靠换标签/换分母提升 |
| 8 | 盲测、统计与交付 | 完整报告、模型卡、复现命令 | 全分母、家族 CI、失败样例与资源记录齐全 |

时间安排以实际资源与 API 速度为准，不再用“请求数/额度”当完成百分比。每个训练和标注任务必须有 job ID/tmux pane、日志、真实退出码、当前 step/已完成样本数；失败重试不假称持续运行。

## 8. 最终需要的三张主表

### 表 A：解析/分类性能

每维模型版本、标签来源、测试家族数、各长度桶数量、F1/exact/有效输出率、CI。Scene 分视觉真值和 caption 可判断子集。LLM 标签与人工标签分栏。

### 表 B：原始视频的 Origin 与 Repair 分数

每维和生成器：视频 UID 数、共同覆盖率、Origin 原始分数、Repair 原始分数、配对差及 CI、耗时/显存。此表只说明分数如何变化，不把分数升高当成改善。

### 表 C：四维确定性实验

每个变换族：有效独立家族数、Origin/Repair 的违约率、配对变化、正确且一致率或方向正确率、常数策略对照、家族级 CI。报告正负对照，不能只挑 Repair 最好看的格子。

## 9. 版本和资源纪律

- 保留旧版本报告；更正结论时说明原因与旧结果作废范围。相邻 audit 的冻结 data/results/splits/runs 不改写。
- 小步 `add → diff --cached → commit → push`；服务器先检查 dirty 状态、备份/提交必要改动，再 `pull --ff-only`。不再将 `reset --hard` 当常规 pull。
- 密钥、原始数据、图片、权重、预测明细默认不进 Git；输出模型、数据和代码 SHA 建立绑定。
- tmux 按任务记录 PID 和退出码，控制脚本只操作本项目自己的 PID；不使用匹配所有 `train_adapter.py` 的宽泛 kill。
- 付费调用固定 provider/model/用途/次数或费用上限，先记账、逐项落盘、断点续跑。数据收集与标注不因需要漂亮结果而无界扩量。
