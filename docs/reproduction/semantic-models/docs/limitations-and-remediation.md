# 边界与弥补方案

本文件把当前四维模型的五条已知边界拆成：**现状证据 → 影响 → 可执行弥补路径 → 验收标准 → 成本与依赖**，
并给出建议顺序。原则不变：不把弱监督数字包装成研究结论，不用"看起来更好"的修补掩盖失败。

当前证据来源：[正式训练报告](formal-training-report.md)、[模型卡](model-cards.md)、[冒烟报告](smoke-report.md)。

| 边界 | 类型 | 最快可做的动作 | 研究级动作 | 外部依赖 |
| --- | --- | --- | --- | --- |
| B1 无人工金标准 / 长桶为空 | 数据+评测 | 冻结评测协议（1 天） | 双人标注 + 长 prompt 撰写（周级） | 标注人力 |
| B2 Action 词表外输出 | 解码+数据 | K400 约束解码 + 拒收（1 天） | 自然动作标注 + 别名表（周级） | 无 |
| B3 Objects 冠词/修饰语 | 纯代码 | 归一化层 + GRiT 映射（0.5–1 天） | 用规范名重训（小时级） | GRiT 词表 |
| B4 Flickr 许可 | 合规 | 发布 VG-only 变体（1 天） | 书面澄清或替换数据源 | 作者/法务回复 |
| B5 Scene 缺真实 Tag2Text | 数据+管线 | 标注指南 + 工程 caption 明确降级（0.5 天） | 跑 Tag2Text + 人工三分类（1–2 周） | 权重与 GPU 授权 |

---

## B1 无人工金标准：所有 F1 是同分布弱监督数字，201+ 词桶为空

**现状证据**
- dev 与 train 同源（VG 模板、K400 模板、Flickr 候选、手写 fixture），family 已隔离但分布相同。
- dev F1：spatial 1.000 / action 0.976 / objects 0.978 / scene 9-9；底座对照 0.990 / 0.313 / 0.495。
- 训练长度桶：spatial 1–14 词 2,292、15–49 词 38；action 全为 1–14 词；objects 15–49 词 1,198、50–99 词 1；
  201–400 与 401+ 为 0（MovieGen 池里 50–99 词只有 20 条、100–200 词 9 条）。

**影响**：不能写"模型在自然 prompt 上达到 0.98"；不能写长度鲁棒性；论文里只能作为工程上限/接口正确性证据。

**弥补路径**

1. **先冻结协议（0.5–1 天，无依赖，必须先做）**
   - 落盘 `docs/evaluation-protocol.md`：任务指标（有序三元组集合 P/R/F1、动作类别映射、实体集合 P/R/F1、Scene macro-F1+混淆矩阵）、
     bootstrap 单元（按家族）、失败样本计入分母、预注册门槛（照 S4：控制复杂度后长桶相对短桶非劣界 3pp）。
   - 冻结"什么算通过"的绝对门槛与"不支持/空结果"判定，再看测试结果，禁止事后改标准。
2. **工程级人工审核（2–3 天，先做小批）**
   - 每任务抽 50 条（`data/formal/v1/*/dev.jsonl` + teacher 候选），做 schema+语义审核，记录分歧类型与一致率。
   - 产出 `docs/labeling-guideline.md`（含空结果、未知类别、多实例、摄影词汇排除表），这是后续标注的前置。
3. **研究级独立金标准（周级，需人力）**
   - 每任务每桶 ≥100 个独立家族（S4 §4 建议），双人标注 + 第三方仲裁，测试家族不与训练/调试重叠。
   - 工作量估算：4 任务 × 5 桶 × 100 家族 ≈ 2,000 家族；按每条 30–60 秒、双人 + 仲裁，约 40–60 人时。
4. **长 prompt 数据构造（与 3 并行）**
   - 以 MovieGen 长 prompt（50–99 词 20 条、100–200 词 9 条）为种子，人工**改写**而非截断：每个种子产出 15–49 / 50–99 / 100–200 / 201–400 各长度版本，
     只在与维度无关时才复用 target；引入新对象/动作/关系必须重新标注。
   - 目标规模：每任务 201–400 词 ≥150 条、401+ ≥50 条，另留独立长测层。
5. **报告口径**：所有现有数字继续标注 `in-distribution weak supervision`；新金标准到位后另出一版报告，两者不混表。

**验收**：独立测试集存在且与训练家族不相交；双人一致率（如 Cohen's κ）与仲裁记录可查；每桶样本量达标；预注册门槛在看结果前冻结。

## B2 Action 需 K400 校验：自然 prompt 上会输出词表外动作

**现状证据**：自然 prompt `chef flips a pancake … waiter pours coffee` → `["flips pancake","pours coffee"]`，K400 无此二类；
试标阶段 5 条 action 请求有 4 条因非 K400 被词表门禁拒绝。

**影响**：直接接入评分会把不存在的动作送进匹配，产生假阴性/假阳性；不能声称"动作解析已可用"。

**弥补路径**

1. **解码端硬约束（1 天，纯代码，推荐先做）**
   - 由锁定 K400 词表 + tokenizer 构建前缀树（trie），用 `prefix_allowed_tokens_fn` 限制生成；
     多动作场景按 JSON 结构分段落约束，或先约束"动作名"片段再拼装。
   - 保留拒收路径：约束后仍解析失败的样本计入 `unknown_action_rate`，不静默丢弃。
   - 这是确定性词表约束，不是"LLM 末端匹配"，不违反接口约束。
2. **数据端补自然表达（周级，效果最好）**
   - 从 MovieGen / 真实 prompt 池抽 300–500 条含动作的 prompt，人工标注对应 K400 类别（双人 + 仲裁）。
   - 建立**K400 别名表**：自然短语 → 规范类别（人工确认，不允许模型自动猜），在指令里给出候选类别或 Top-k 检索结果。
   - 训练时加入"无匹配动作 → 空数组"的负样本，明确教模型拒答而不是编造。
3. **评测端**：报告 `未知动作率`、`类别覆盖数`、`多动作完整率`，并按 S4 的分桶指标出表。

**验收**：自然 prompt 测试集 `unknown_action_rate` < 5%（可调门槛，需预注册）；未映射动作有显式拒收记录；K400 覆盖类别数报告。

## B3 Objects 需归一化：输出带冠词与修饰语

**现状证据**：`a cat` / `A young woman` / `a stack of books` 直接出现在 target 里；`entities` 未与 GRiT 标签空间对齐。

**影响**：下游匹配会因冠词/复数/别名误判；无法直接与 GRiT/UMT 输出对齐。

**弥补路径**

1. **确定性归一化层（0.5–1 天，纯代码）**
   - 冠词/量词/所有格剥离（`a/an/the/two/their…`）→ 复数/单数归一 → 别名映射 → GRiT 标签；
     原文与归一化结果同时保留，便于审计与回退。
   - 无法映射的实体标 `unmapped`，计入 `unmapped_rate`，不静默删除。
2. **取到真实标签空间**：从官方 GRiT/UMT 资产（`grit_b_densecap_objectdet.pth` 配套 vocab）导出类别表，
   建立 `configs/vocab/grit_labels.json` 与映射表 `configs/vocab/entity_aliases.json`，两者都人工复核。
3. **训练端**：用归一化后的规范名重训 objects adapter（约 20 分钟），并在指令中写明"输出规范名、不带冠词"。
4. **协议**：把 bodypart/clothing/scene 等类型的取舍写进标注指南（当前 Flickr 是 flag 不是删除）。

**验收**：归一化前后 P/R/F1 对比表；`unmapped_rate` 报告；归一化层单元测试覆盖冠词、复数、别名、不可映射四类。

## B4 Flickr 许可未澄清：Objects adapter 不得随数据再分发

**现状证据**：Flickr30k Entities README 只声明图片受 Flickr ToS 约束，annotation 的训练/再分发许可未明确；
当前 7,368 条 objects 训练样本里 4,000 条来自 Flickr。

**影响**：adapter 的发布与论文数据披露受限；不能声称"数据可自由再分发"。

**弥补路径**

1. **合规动作（立刻）**：准备两个版本
   - `objects-vg-only`：只用 VG 关系端点 + VG region descriptions 训练（可发布）；
   - `objects-full`：含 Flickr，仅内部研究使用，发布时明确排除。
2. **澄清（外部依赖）**：向 Flickr30k Entities 作者发邮件确认 annotation 的训练与再分发条款，保留书面回复。
3. **替换数据源（1–2 天可落地）**
   - **Visual Genome region_descriptions**（已验证可下载，127MB ZIP，CC-BY-4.0）：自然语言区域描述含对象短语，
     可提供比关系模板更自然的 objects 监督；
   - COCO/Open Images 的类别与检测标注（CC-BY 4.0 / CC-BY）作为词表与负样本来源；
   - 注意：GRiT/UMT 在视频上的检测输出属于模型预测，只能作为弱标签，不能当人工标注。
4. **论文披露**：写清每个任务的数据来源、许可与使用范围；使用过 MovieGen prompt 的批次不得再作为独立 MovieGen 测试。

**验收**：存在可发布的 VG-only adapter；发布清单与许可清单逐条对应；论文数据表含许可列。

## B5 Scene 缺真实 Tag2Text 数据：训练数据是手写工程 caption

**现状证据**：scene 训练集 81 条（24 个手写家族 + 5 条 teacher），caption 由本项目手写；
dev 9/9 exact、macro-F1 1.0 只说明接口可用；0.6B 版本需要停止约束，8B 版本自然收敛。

**影响**：不能声称真实管线（prompt + Tag2Text 单帧 caption）准确率；`insufficient` 协议未经真实分布检验。

**弥补路径**

1. **先落标注指南（0.5 天）**：明确 supported / contradicted / insufficient 的判定边界，
   尤其是"prompt 没有场景要求""宽泛术语（water vs ocean/river）""caption 无信息"三类；写进 `docs/labeling-guideline.md`。
2. **跑真实 Tag2Text（1–2 天，需授权）**
   - 需要：Tag2Text 权重（需另行下载授权）、GPU（可与训练共用空闲卡）、一帧/视频的解码脚本；
   - 数据：优先用冻结审计里的 VBench 生成视频（注意不得用于训练已反复调参的审计集，只作盲测）；
   - 产出：(prompt, caption) 对 → 人工三标签标注，家族按 prompt/视频分组。
3. **规模与评测**：每类 ≥100 家族，双人标注 + 仲裁；报告 macro-F1、每类召回、混淆矩阵、`insufficient` 召回与
   "无场景要求"专项准确率。
4. **架构对照（可选，1 天）**：同一批数据上训练三分类头版本，与生成式 + 标签边界约束版本对照；
   决策记录 D2 允许把它作为对照实验而不是默认方案。
5. **上限说明**：caption 幻觉（Tag2Text 看到但视频没有 / 视频有但没描述）不是文本模型能修的，
   必须在报告中单独列出这一类失败并给出占比。

**验收**：真实 caption 测试集上的 macro-F1 与混淆矩阵；人工一致率；幻觉类失败单独统计；`insufficient` 协议有数据支持。

## 建议执行顺序（按性价比）

| 顺序 | 动作 | 工作量 | 依赖 | 立刻可得的收益 |
| ---: | --- | --- | --- | --- |
| 1 | B3 归一化层 + GRiT 映射 | 0.5–1 天 | 无 | objects 指标可对齐下游 |
| 2 | B2 解码约束 + 拒收 | 1 天 | 无 | Action 输出不再越界 |
| 3 | B1.1 评测协议 + B1.2 小批审核 + 标注指南 | 3–4 天 | 无 | 后续所有数字有统一口径 |
| 4 | B4 发布变体（VG-only）+ 许可澄清邮件 | 1 天 + 等待 | 外部回复 | 发布路径通畅 |
| 5 | B5.2 真实 Tag2Text 数据 | 1–2 周 | 权重/GPU 授权 | Scene 具备研究级证据 |
| 6 | B1.3/B1.4/B2.2 双人标注与长 prompt 构造 | 周级 | 标注人力 | 论文主结果 |

## 不要做的事

- 不用最近邻把词表外动作"猜"成 K400 类别，也不在推理端加 LLM 匹配阶段。
- 不截断长 prompt 造短样本，不用重复变体冒充独立家族。
- 不把 teacher 输出、GRiT 预测或弱监督模板写成人工金标准。
- 不因为指标好看就删除失败样本；解析失败必须留在分母里。

## 需要用户决策

1. 是否授权下载 **Tag2Text 权重**并在冻结 VBench 视频上跑单帧 caption（B5，最大缺口）。
2. 是否同意先用 **VG region_descriptions**（127MB，CC-BY-4.0）替代 Flickr 训练 objects（B4）。
3. 标注人力安排：先做 50 条小批审核，还是直接进入每桶 100 家族的双人标注（B1）。
4. 长 prompt 构造：接受人工改写（更贵但正确），还是先用 MovieGen 现有长 prompt 做小规模试点（B1.4）。
