---
name: vbench-eval
description: Configure and run this repository's VBench 16-dimension evaluation, compare original VBench with nine selected repairs and seven accelerated dimensions, inspect cache provenance, and validate GPU runs.
---

Run from the VBench Repair checkout. Read `configs/eval.yaml` and `docs/evaluation.md` for the current command contract; use `configs/reproduction/paper-methods.json` for selected methods. Do not infer paper methods from the legacy per-metric CLI defaults.

1. Prepare a JSON/JSONL input manifest with actual video paths, prompts, dimensions, and dimension metadata. Standard suites can use `scripts/prepare_vbench_inputs.py`; arbitrary filenames are not a reason to guess prompts or labels. Paths inside the input manifest are relative to that manifest unless `video_root` is set. Subject Repair needs the official `subject_en` annotation. Dynamic aligned-v1 needs native square RGB videos with exactly 16 frames at 8 FPS; do not silently resample them.
2. Use the fixed runtime assets from `scripts/restore_paper_runtime.py`, or an already verified `assets.json`. The root uv environment is Python 3.11.14; visual and semantic workers use separate, ABI-compatible uv environments that share existing model dependencies. Never synchronize `models` into a shared paper runtime or install packages into its thin environments.
3. Edit the flat YAML (`version: 1`), then run `uv run python scripts/eval.py --config <yaml> --plan`. YAML paths resolve from the YAML directory; command-line path overrides resolve from the current directory. `${ENV_NAME}` requires a defined variable. Unknown keys, aliases and duplicate keys are errors.
4. Run `uv run python scripts/eval.py --config <yaml>` or `./scripts/eval.sh --config <yaml>`. Default `--backend ours` runs nine selected repairs plus seven accelerated dimensions. `--backend official` runs original VBench in one process per selected GPU; legacy `repair` / `origin` names are accepted. `--backend both` runs 32 distinct dimension/backend tasks. `--dimensions paper` restricts to nine; `--dimensions scene color` selects named dimensions. GPU integers index inherited `CUDA_VISIBLE_DEVICES`; workers see one device as `cuda:0`. Do not kill unrelated GPU processes.
5. Check `summary.json` for complete coverage, `plan.json` for methods and source/model/runtime identity, and `events.jsonl` plus each stage's `worker.log` for failures. A null score is an unscored input, not zero. Partial coverage must not be described using the successful subset's mean as the full score. Official and accelerated aggregates retain upstream reducers, including MUSIQ's /100 dataset scale.
6. Repeated runs use new output directories and reuse verified stage artifacts. Cached scores are explicitly marked; they are not fresh GPU inference. `--no-reuse` prevents previous-run inference reuse; identical GRiT frames and ViCLIP video features can still be shared inside this fresh run, with explicit hit/miss receipts. Keep the cache while outputs link to it. Cache identities include ordered media, paths, prompt/metadata, model hashes, source, environment, and GPU runtime; incompatible visual protocols are not interchangeable.

Never modify frozen `data/`, `results/`, `splits/`, or `runs/`. Report representative GPU smoke, numerical replay, and full research reproduction separately. Record the code SHA, GPU identities, input count/media duration, wall time, coverage and cache status when reporting speed. Publishing, training, or rewriting the paper's result tables are separate tasks, not implicit effects of evaluation.

For acceleration changes, use `scripts/benchmark_accelerated_dimension.py` and the fixed cohort in `docs/plans/2026-10-08-speed32-optimization.md`. Each of the seven accelerated dimensions must preserve complete input identity and satisfy per-video `abs(candidate - official) <= max(1e-6, 0.01 * abs(official))`. Nine-repair comparisons instead use their selected repair reference, including unchanged failure states. Establish all-16 timings, then optimize and validate one dimension at a time; the four GRiT dimensions may be handled together. Report actual end-to-end wall time against original single-process VBench, not a sum of isolated timings or an official baseline penalized by repeated process startup.
